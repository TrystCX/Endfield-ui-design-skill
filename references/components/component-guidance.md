# 组件设计指导

本文件把源仓库的组件规范压缩成可跨技术栈执行的决策。具体数值和证据入口见 `components/README.md`、`token-inventory.md` 及源仓库对应文档。

## 按钮与导航

- `action`：主要行动，使用信号色填充和墨字；一个视图通常只有一个主导行动。
- `control`：中性控制，亮色主题是深灰底，暗色主题可用半透明白底。
- `light`：浅色或弱强调行动，保留可读的底色差。
- `danger`：红色语义底与白字，不能用红色装饰替代危险说明。
- 悬停主要换底色和文字色；按下进入更深一档；保持尺寸稳定，不上浮、不放大。
- 图标和文字之间可有细竖线，但不要为装饰占用行动信息的空间。
- 侧轨、顶栏、全屏菜单和页签表达当前位置；当前状态使用滑动底块、边条、箭头或填充反转。

## 面板、卡片与媒体

- 面板默认直角、1px 语义边线、无重阴影；层次优先依靠表面差。
- 媒体卡保留直角或微圆角，播放记号使用小黄色方块；不使用巨大的半透明圆形播放按钮。
- 列表行、数据行和物品格可以闭合边界，但不把所有内容包装成独立卡片。
- 图片查看、悬浮卡和详情面板应从触发内容继承主题、方向和层级。

## 表单

- 字段标签、帮助、错误和成功说明要有真实文本；错误状态同时给颜色、图标和文字。
- 输入框可用凹陷底或语义描边表达，但焦点环必须独立可见。
- 复选、单选、开关、分段选择和滑块要有形状/位置差异；状态不只靠颜色。
- 选择、组合框、日期、文件上传和标签输入需定义键盘、空值、加载、无结果和错误状态。
- 复杂浮层使用可靠的无障碍基元；不要手写一套只处理鼠标的下拉菜单。

## 反馈与浮层

- Alert 是页面内的持续反馈，Toast 是短暂反馈；二者的内容和持久性不同。
- Loader、Skeleton 和 Progress 保持布局稳定；确定进度使用黄色轨道，量值图表使用蓝色数据角色。
- Dialog、Drawer、Popover、Tooltip、HoverCard 和 DropdownMenu 从触发侧进入，管理焦点、Escape 和外部点击。
- 叠层顺序遵循 `z-float → z-nav → z-overlay → z-toast → z-loader`。

## 数据展示

- 表格、数据行、统计块、Sparkline 和时间线以清晰读数为签名；不要为密度伪造遥测。
- 颜色表达状态、量值、地区、危险和稀有度时，保留文字或形状冗余。
- 选中、排序、展开、分页和横向滚动应有稳定的键盘和触屏行为。

## Game 实机风格边界

`packages/ui/src/game` 是独立入口，包含照游戏内界面复刻的控件和 30 张官方图片。它不是主组件库的通用变体，也不是本 Skill 的资产来源。需要游戏 UI 时，先读源仓库 `docs/design/game/README.md` 的风险章节；用原创几何占位和主组件系统复现结构时，明确说明这是社区证据或推断。
